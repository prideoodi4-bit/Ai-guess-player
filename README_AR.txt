تحدي حزر اللاعب — نسخة بحث ويب
Python 3.11+، مكتبات Python القياسية فقط، لا تحتاج pip install.
بنك الاختيار 150 لاعباً كما اتفقنا؛ البحث يوسع المعلومات عن كل لاعب.

إعداد Railway بعد رفع الملفات:
BOT_TOKEN = توكن Telegram
GROQ_API_KEY = مفتاح Groq
GROQ_MODEL = openai/gpt-oss-120b
WEB_SEARCH = 1
DB_PATH = /data/bot.db
القيم بدون علامات اقتباس في Variables.
أضف Volume مربوطاً بخدمة البوت واجعل Mount Path = /data.
DB_PATH وحده لا ينشئ Volume.
Start Command = python bot.py، أو اترك Dockerfile يشغله.
Replicas = 1، عطّل Serverless، لا تستخدم Cron أو HTTP Healthcheck.
لا يحتاج Domain أو PORT لأنه يستخدم Telegram Long Polling.
أوقف كل نسخة أخرى تستخدم نفس BOT_TOKEN.
عند نجاح تهيئة Telegram تظهر Bot ready وweb_search=True في Logs.
هذه ليست تجربة حيّة لمفتاح Groq؛ اختبر /ask في كيم.

الخطوات داخل Telegram:
أضف البوت إلى الكروب واسمح إرسال الرسائل.
لا يحتاج أدمن عادةً، ولا يلزم تعطيل Privacy Mode لأننا نستخدم الأوامر.
داخل الكروب أو القسم: /newgame ثم حسابان مختلفان /join.
كل مشارك عنده لاعب مخفي مختلف، والبداية عشوائية.
/ask هل لعب سابقاً في باريس سان جيرمان؟
/guess ميسي
أول تخمين صحيح حسب ترتيب Telegram يفوز.
الأسئلة بالتناوب، والتخمين متاح للاثنين بأي وقت.
التخمين الخطأ يستهلك الدور إذا كان دورك.
/pass يمرر الدور، /stop لصاحب الكيم أو الأدمن.
/status الحالة، /history أسئلتك، /score انتصارات الكروب.
/rules قائمة أندية التوب وتعريف استخدامها.
لكل Topic كيم مستقل، والنتائج مشتركة على مستوى الكروب.
قائمة الأوامر تنضاف تلقائياً، والـwebhook القديم ينحذف تلقائياً.
إذا عندك بوتات متعددة استخدم /ask@اسم_بوتك وهكذا.

كيف يجيب:
1. التكرار المطابق ينفحص محلياً بلا طلب API.
2. طلب Groq يفحص صلاحية السؤال وتكراره بالمعنى.
3. السؤال الجديد المقبول ينفذ طلباً ثانياً مع browser_search وtool_choice=required.
   البحث ينفذ على خوادم Groq؛ لا يحتاج مفتاح محرك بحث منفصل.
4. الموديل يبحث عن اسم اللاعب والسؤال وتاريخ الآن بتوقيت UTC.
   لا نرسل قوائم النادي القديمة في طلب البحث حتى لا يرجع إليها.
5. يفضّل المصادر الرسمية للانتقالات والنادي الحالي، ويبحث عن المسيرة
   للأسئلة التاريخية. إن لم يجد دليلاً كافياً يعيد مجهول ويحفظ دورك.
6. البوت يتحقق من بنية النتيجة وقيم نعم/لا وروابط المصادر.
   نتيجة بلا مصادر لا تُعرض كجواب مؤكد.
7. اسم اللاعب، النص الحر والمصادر لا تظهر بالكروب لأن الرابط قد يكشف الاسم.
   المصادر وتاريخ التحقق تُحفظ في سجل السؤال داخل SQLite للتدقيق.

الموديلات التي تدعم البحث هنا:
openai/gpt-oss-120b (افتراضي)، openai/gpt-oss-20b.
لا تختار Qwen في وضع البحث لأنه لا يدعم هذه الأداة حالياً.
البحث ليس متوافقاً مع Structured Outputs، لذلك نطلب نتيجة JSON محددة
ونتحقق منها محلياً. الرد المشوه أو الناقص يُرفض ويحفظ الدور.
كل سؤال جديد قد يحتاج طلبين، والبحث قد ينفذ أكثر من جولة داخل Groq.
هذا أبطأ ويستهلك توكنات أكثر من نسخة البنك وحده.
لا نضمن توفر Browser Search أو مجانيته وحصته لحسابك؛ راجع Groq Console
واختبره على حساب Free قبل الاعتماد عليه. البرنامج لا يرقي اشتراكك تلقائياً.
إذا البحث غير متاح أو انتهت الحصة، لا نجيب من البنك القديم بصمت.
Gemini الاحتياطي القديم لا يستعمل في وضع البحث لأنه غير مربوط ببحث ويب.

معاني الأسئلة:
أندية التوب: قائمة لعبة ثابتة موجودة في TOP_CLUBS بـbot.py، وليست تصنيفاً
عالمياً موضوعياً. /rules يعرضها. السؤال يعني النادي الحالي إلا إذا قال سابقاً.
الدين: يتطلب تصريحاً علنياً موثوقاً أو تقريراً موثوقاً ينقل تصريح اللاعب.
لا يُستنتج من الجنسية، الاسم، العرق، المظهر أو الاحتفالات.
غياب الدليل لا يعني لا؛ يعني غير متوفر. والأسئلة الشخصية غير المثبتة كذلك.
السؤال الذاتي أو الغامض قد يحتاج إعادة صياغة.
البحث والذكاء الاصطناعي قد يخطئان أو يفوتهما مصدر؛ لا توجد ضمانة 100%.
فحص الروابط لا يثبت آلياً أن كل معلومة في الصفحة صحيحة أو حديثة.

منع التكرار:
لكل مشارك داخل الكيم، وليس عبر كل الألعاب.
التكرار المطابق بعد توحيد الحروف محلي، والتكرار المعنوي بواسطة AI.
المنافس يستطيع السؤال عن نفس الخاصية لأن لاعبه مختلف.
السؤال المجهول يُحفظ أيضاً، لكن لا يستهلك الدور.
المكرر والمرفوض وفشل API لا يستهلكان الدور.
حد 60 سؤال محفوظ لكل مشارك، و5 ثوانٍ بين طلبات AI.
عند 429 ينتظر Groq حسب Retry-After، أو 60 ثانية عند غيابها.

الحفظ:
SQLite يحفظ الكيم، النتائج، سجل الأسئلة ومصادر الأجوبة.
ضعه في /data مع Volume. لنسخة احتياطية أوقف البوت وانسخ مجلد /data كله.
لا ترفع ملفات قاعدة البيانات لأنها تحتوي هويات اللاعبين المخفية.
لا ترفع مفاتيحك إلى GitHub ولا ترسلها بالكروب.
.env.example مثال ولا يقرأه البرنامج تلقائياً.

وضع البنك القديم اختياري فقط:
WEB_SEARCH=0 يرجع للوضع السابق، ويستخدم بيانات لقطة 3 أكتوبر 2026.
حينها فقط GEMINI_API_KEY يفعل الاحتياطي وGEMINI_MODEL يختار الموديل.
هذا الوضع لا يبحث على الإنترنت ولا يحقق طلب البحث الحالي.

أخطاء التشغيل:
401/403: مفتاح أو صلاحيات حساب؛ في البحث قد تكون الأداة غير متاحة.
400/404: راجع اسم GROQ_MODEL ودعم browser_search.
402: راجع خطة الحساب؛ لا يغير البرنامج الفوترة.
429: حصة طلبات أو توكنات أو بحث؛ انتظر.
409 Telegram: نسخة ثانية بنفس التوكن؛ أوقفها.
تعذر جواب موثوق: قد يكون بحثاً ناقصاً أو استجابة ناقصة/مشوهة.
